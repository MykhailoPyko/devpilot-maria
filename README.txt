ОНОВЛЕННЯ 1.0.3
Повідомлення Марії зліва: через 5 секунд без скролу на кожному завантаженні сторінки. Закриття діє лише до оновлення. Плавна поява 700 мс і закриття 360 мс; reduced-motion підтримується. Три кнопки відкривають чат і надсилають обраний запит. Зірочка переміщена ліворуч від обличчя.

ДЕПЛОЙ: розпакуйте архів; для повної роботи функцій використовуйте Git deployment або `npm run deploy` (Netlify CLI). Build: npm run build; Publish: dist. Просте завантаження dist через Drop не встановлює серверну функцію чату. Налаштуйте змінні з .env.example у Netlify.

DEVPILOT STUDIO — NETLIFY + N8N + CLAUDE
Подготовленный комплект интеграции. Реальные ключи не включены.

ЧТО В КОМПЛЕКТЕ
- public/: исходники лендинга, адаптивная мобильная версия, чат, приглашение Марии после 5 секунд бездействия.
- netlify/functions/chat.mjs: серверный посредник между браузером и n8n.
- netlify.toml: настройки публикации и функции /api/chat.
- n8n/DevPilot-Maria.json: workflow для импорта (19 узлов, выключен до настройки).
- docs/system-prompt.txt: полный системный промпт Марии (также встроен в workflow).
- docs/supabase.sql: отдельная таблица заявок, без изменения существующих таблиц CRM.
- .env.example: список переменных окружения, БЕЗ настоящих ключей.
- tests/: локальные автоматические проверки.

БЫСТРЫЙ ПОРЯДОК ЗАПУСКА
1. Supabase: выполните docs/supabase.sql в SQL Editor вашего проекта.
2. n8n: импортируйте n8n/DevPilot-Maria.json и назначьте credentials, описанные ниже.
3. В узле Configuration задайте URL Supabase и ID Telegram-группы.
4. Опубликуйте/активируйте workflow и скопируйте Production URL вебхука.
5. Загрузите ВЕСЬ проект в GitHub и подключите репозиторий к Netlify.
6. Добавьте четыре переменные в Netlify и выполните deploy. Затем пройдите приёмку в конце инструкции.

ВАЖНО О ЗАГРУЗКЕ NETLIFY
Это проект с серверной функцией. Простого перетаскивания папки dist в Netlify Drop недостаточно: так не будет собрана и опубликована функция чата.
Рекомендуемый путь: GitHub → Netlify → Import an existing project → выбрать репозиторий.
Корневая папка проекта должна содержать netlify.toml, package.json, public, scripts, netlify/functions, n8n и tests.
Build command: npm run build
Publish directory: dist
Functions directory: netlify/functions
Настройки уже записаны в netlify.toml. Сборка копирует public в dist и запускает тесты. Папка dist создаётся автоматически; загружать её в Git не нужно.
Альтернатива из корня проекта с Node.js 22+: npx netlify-cli deploy --build --prod
CLI предложит войти и выбрать/создать сайт. Для проверки локально: npx netlify-cli dev.
Для локального режима задайте ALLOWED_ORIGIN=http://localhost:8888 и поместите остальные значения в локальный .env (не отправляйте его в Git).

НАСТРОЙКИ NETLIFY
Добавьте в Project configuration → Environment variables (доступны Functions/runtime):
N8N_WEBHOOK_URL — HTTPS Production URL, например https://n8n.example.com/webhook/devpilot-maria
N8N_WEBHOOK_SECRET — случайная строка, совпадает с Header Auth входящего n8n Webhook.
CHAT_STATE_SECRET — ДРУГАЯ случайная строка не короче 32 символов; подписывает состояние диалога.
ALLOWED_ORIGIN — точный адрес сайта, например https://devpilot.netlify.app (без пути, без / в конце).
Если используется свой домен, укажите его канонический адрес. Для preview-доменов настройте соответствующее значение в их deploy context. Не используйте '*'.
Сгенерировать каждый секрет отдельно: node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
Не вставляйте ключи в HTML, JS браузера, netlify.toml или workflow JSON. .env.example — только шаблон.
После изменения переменных выполните новый deploy.

НАСТРОЙКИ N8N
Импорт: меню workflows → Import from File → DevPilot-Maria.json.
Workflow использует стандартные узлы Webhook, Code, IF, HTTP Request, Respond to Webhook и Telegram; community nodes не нужны.
В Configuration замените:
- supabaseUrl: https://YOUR_PROJECT.supabase.co → URL вашего Supabase проекта;
- telegramChatId: REPLACE_WITH_YOUR_GROUP_CHAT_ID → ID группы менеджеров/тимлида;
- model: предустановлен claude-haiku-4-5-20251001. Можно указать другую доступную вашему Anthropic-аккаунту модель с поддержкой tool use. Если меняете семейство, проверьте допустимость temperature и max_tokens.

Credentials (назначить вручную после импорта):
A. Incoming request → Header Auth:
   Name: X-DevPilot-Secret
   Value: то же значение, что N8N_WEBHOOK_SECRET в Netlify.
B. Claude → Generic Credential Type → Header Auth:
   Name: x-api-key
   Value: ваш Anthropic API key.
   Заголовок anthropic-version уже задан в узле, отдельно менять не нужно.
C. Save lead И Mark notified → Generic Credential Type → Custom Auth:
   JSON:
   {"headers":{"apikey":"YOUR_SUPABASE_SERVICE_ROLE_KEY","Authorization":"Bearer YOUR_SUPABASE_SERVICE_ROLE_KEY"}}
   Вставьте ваш legacy service_role JWT key в оба места. Не используйте anon/publishable key. Этот credential существует только в n8n.
D. Notify Telegram → Telegram API credential:
   Введите токен бота из BotFather. Добавьте бота в группу и разрешите ему отправлять сообщения.

Проверьте, что все узлы получили credentials. Опубликуйте/активируйте workflow.
Используйте именно Production URL, не Test URL: тестовый webhook работает только во время ручного прослушивания.
Для отладки можно временно включить сохранение тестового выполнения. По умолчанию сохранение содержимого успешных, ошибочных и ручных executions отключено, чтобы контакты не дублировались в журналах.

КАК РАБОТАЕТ ДИАЛОГ
- Первое приветствие и приглашение после 5 секунд — готовые тексты, не вызывают платный AI.
- Для каждого сообщения: браузер → Netlify Function → n8n → Claude → ответ браузеру.
- Мария консультирует кратко, собирает только задачу, имя и один контакт (телефон, Telegram или email).
- Цена, сроки, бюджет, название компании и подробное ТЗ не обязательны. Мария не должна придумывать цены и обещания.
- Имя/контакт, указанные сразу, не запрашиваются повторно. Точные данные можно исправить сообщением в чат.
- Когда всё готово, показывается карточка заявки. Посетитель ставит согласие на передачу контакта и нажимает «Надіслати заявку».
- Только после успешной записи в Supabase сайт подтверждает сохранение.
- После ответа браузеру workflow отправляет уведомление в Telegram и отмечает notification_status='sent'.
- Повтор того же запроса не создаёт вторую запись и повторное уведомление: request_id — уникальный ключ. Новая заявка/новый диалог могут создать новый ID.
- Если Telegram недоступен, заявка уже сохранена; notification_status остаётся pending. Проверьте такие записи и доставку вручную. Автоматический повтор Telegram-уведомлений и создание лида в существующих таблицах CRM в этот комплект НЕ включены. Таблица devpilot_web_leads — отдельный входящий список, её можно связать с вашей CRM отдельным workflow.

ПОВЕДЕНИЕ ВСПЛЫВАЮЩЕГО СООБЩЕНИЯ
- 5 секунд без прокрутки в открытой вкладке.
- Таймер сбрасывают прокрутка страницы и колёсико мыши (включая переключение слайдов на ПК). Движение мыши и обычные нажатия таймер не сбрасывают.
- В скрытой вкладке таймер остановлен, после возвращения отсчитывается заново.
- Не показывается после фокуса в поле чата или начала диалога. Геометрия скрытого слайда не блокирует показ.
- Одно появление на сеанс вкладки (sessionStorage), без звука, автоперехода и захвата фокуса.
- Крестик и Escape закрывают сообщение. Кнопка «Запитати Марію» открывает раздел чата.
- Плавное появление 650 мс, пастельная карточка, AI-маркер, крупные зоны нажатия.
- В режиме reduced motion анимация отключена.

ПЕРСОНАЛЬНЫЕ ДАННЫЕ И ЛИМИТЫ
Сообщения передаются Netlify, n8n и Anthropic для ответа. После подтверждения имя, задача и контакт сохраняются в вашей Supabase и отправляются в вашу Telegram-группу. Полная переписка в таблицу заявок не записывается. В браузере состояние диалога находится только в памяти вкладки; после перезагрузки диалог начинается заново. В sessionStorage хранится только факт показа приглашения.
Подпись состояния защищает от подмены, но не является шифрованием. Состояние передаётся по HTTPS и не должно попадать в логи. Сеанс действителен 2 часа, история ограничена последними 20 сообщениями и полями заявки, максимум 30 запросов AI за диалог.
На функции задан rate limit: 12 запросов в минуту на IP/домен. Проверьте применение правила в Netlify deploy log. Ограничение не заменяет общий лимит бюджета в кабинете провайдера AI.
Таймауты: HTTP n8n — 35 секунд, Netlify → n8n — 45 секунд, браузер — 50 секунд. При ошибке есть повтор без потери текста, при просроченном сеансе — новая беседа.
Для публичного запуска добавьте собственную политику конфиденциальности и реальные реквизиты оператора данных; они не были предоставлены и не выдуманы.

ПРИЁМКА ПОСЛЕ ПОДКЛЮЧЕНИЯ
1. Откройте сайт, не взаимодействуйте 5 секунд — приглашение появится. Закройте, обновите страницу — не появится снова в той же вкладке.
2. На новом сеансе прокрутите страницу на 3-й секунде — приглашение должно ждать ещё 5 секунд.
3. Откройте чат. Напишите: «Мене звати Олена, потрібен сайт для студії, Telegram @olena_test». Используйте свой настоящий тестовый контакт при реальной отправке.
4. Убедитесь, что Мария не просит повторно все данные, а карточка заявки содержит правильные поля.
5. Исправьте контакт сообщением — карточка обновится, галочка согласия сбросится.
6. Подтвердите заявку — должна появиться ровно одна запись в devpilot_web_leads и сообщение в Telegram.
7. На временной ошибке сети повторите отправку — существующий request_id не дублируется.
8. На мобильном устройстве проверьте обычный скролл, закрытие приглашения, клавиатуру и карточку заявки.

ЧТО ПРОВЕРЕНО ЗДЕСЬ
15 автоматических тестов: проверка входа/секретов, подписанное состояние, согласие, повторная отправка, ошибки upstream/БД, связность workflow, компиляция Code nodes, структурированный ответ AI, защита от выдуманного контакта, HTML-экранирование Telegram, поведение таймера и скрытой вкладки.
Настоящий импорт/выполнение на вашем n8n, вызовы Claude, запись в Supabase, доставка Telegram и публикация Netlify требуют ваших credentials и не выполнялись.
Браузерная визуальная проверка в этой среде недоступна. Проверьте итоговый вид на своём Netlify preview перед публичным запуском.
